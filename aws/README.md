## Credit activity entry point
AWS currently lists these five onboarding activities for additional credits. Open **Explore AWS** on AWS Console Home and select **Earn AWS credits** when available. Follow the exact activity shown for the account; creating a similar resource does not establish reward eligibility.

Before each activity, privately record account eligibility, displayed completion deadline, available credits and expiry, region, selected configuration, estimated usage, and cleanup plan. Check the account's actual reward terms instead of assuming a fixed award or deadline. Never publish the account ID or billing exports.

Source checked September 12, 2026: [AWS — Earning additional credits](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/free-tier-plans-activities.html). AWS describes EC2, RDS, Lambda, and Bedrock activities as consuming credits through service charges. [Free Tier FAQs](https://aws.amazon.com/free/free-tier-faqs/) explain account-specific credit and expiration checks. Recheck these sources and console terms before execution.

## Completion workflow
1. Choose one starter and define the minimum acceptance checks.
2. Verify cost coverage for the service and dependencies. Stop if $0 additional out-of-pocket cost cannot be reasonably supported.
3. Follow the console activity using the smallest suitable eligible configuration.
4. Capture sanitized functional and security evidence.
5. Remove temporary resources and verify dependent-resource cleanup.
6. Check the activity reward separately from technical completion; record pending rewards without rerunning billable work.
7. Review delayed billing data and finalize cost closure.

Keep engineering status, reward status, and cost-closure status distinct. A functioning lab can have a pending reward; unresolved resource cleanup remains a completion blocker. Optional screenshots and enhancements do not reopen accepted milestones.
